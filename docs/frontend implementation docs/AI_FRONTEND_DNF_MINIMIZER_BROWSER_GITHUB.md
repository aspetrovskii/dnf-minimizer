## 1. Цель продукта

Десктопное приложение **минимизации ДНФ** булевой функции заданной на всех `2^N` наборах переменных (значения только `0` или `1`). Алгоритм на бэкенде уже реализован (минимизирующие карты + эвристики). Фронтенд:

- вводит `N` и вектор значений функции;
- пошагово вызывает `Minimizer::makeStep()`;
- визуализирует таблицу из `returnTable()` с закреплёнными областями и скроллом;
- показывает минимальную ДНФ после завершения (из `returnAns()`), с копированием в буфер по клику;
- визуально опирается на **макет-скриншот** (раздел 3); **pixel perfect не требуется**.

**Не использовать** `Minimizer::getAnswer()` — ответ строить из `returnAns()` / `MinDNF` / `Disjunct`.

## 4. Бэкенд: API и семантика (обязательно к прочтению)

### 4.1. Конструктор

```cpp
explicit Minimizer(vector<ll> s, ll n, QObject *parent = nullptr);
```

- `n` = число переменных `N`.
- `M = (1 << n)` — число строк таблицы и длина `s`.
- Ожидается `s.size() == M`; элементы `0` или `1`.
- Таблица: для каждого `mask` от `1` до `M-1` создаётся столбец `table[mask]` длины `M`, инициализированный нулями.
- `func = s` (копия).

При передаче в `Minimizer` из Qt: передавать **копию** вектора корректного размера; при желании передать `this` как `parent` для владения в дереве QObject.

### 4.2. Шаги

```cpp
void makeStep();
ll returnStage();
```

**Начальное состояние:** `stage == 0`, таблица по смыслу «до step1» — в ячейках нули (не закрашено с точки зрения UI для стадии заливки).

**Логика `makeStep()` (критично):**

- Если `stage == 0` → выполнить `step1()`.
- Если `stage == 1` → выполнить `step2()`.
- Если `stage == 2` → выполнить `step3()`.
- Если `stage == 3` → выполнить `computeAnswer()`.
- Если `stage < 4` → `++stage`.

То есть **после** первого вызова `makeStep()` значение `returnStage()` становится **1**, и т.д. После четвёртого вызова `returnStage() == 4`.

**Соответствие номера шага алгоритма и заливки ячеек:** в `table[mask][i]` хранится целое `0…4`:

| Значение | Смысл для UI |
|----------|----------------|
| `0` | Не закрашено (белый фон ячейки, только полупрозрачность не нужна или alpha 0) |
| `1` | Закрашено на шаге 1 (`step1`) — самый «ранний» жёлтый оттенок |
| `2` | Шаг 2 |
| `3` | Шаг 3 |
| `4` | Шаг 4 (финальная разметка в `computeAnswer`) — краснее |

Заливка **полупрозрачная** для значений `1…4`; `0` — без цветной заливки (белый).

### 4.3. Таблица

```cpp
map<ll, vector<ll>, PopcountComparator> returnTable();
```

- Ключ = маска столбца (`1 … M-1`).
- Порядок итерации `map` = порядок столбцов на экране: сначала по возрастанию `__builtin_popcount(mask)`, при равенстве — по возрастанию числового значения `mask` (`PopcountComparator`: `lhsCount < rhsCount`, иначе `lhs < rhs`).
- Пример для `N=3`: маски в порядке `1,2,4,3,5,6,7` → подписи столбцов `A, B, C, AB, AC, BC, ABC` при соглашении об именах бит (ниже).

### 4.4. Ответ

```cpp
MinDNF returnAns();
```

`MinDNF` содержит `vector<Disjunct> mindnf` и `ll size` (вес).

`Disjunct`:

- `ll mask` — какие переменные входят в импликант (биты маски).
- `ll kit` — набор значений на этих позициях для куба; `get() == mask & kit`.

Для **отображения и копирования** одного литерала по биту `k` (если `(mask >> k) & 1`):

- если `(kit >> k) & 1` → переменная в прямой форме;
- иначе → отрицание переменной.

Имена: бит `0` → `A`, бит `1` → `B`, … бит `6` → `G` (достаточно для `N ∈ [2,7]`).

Импликанты в визуальном «тетрадном» виде — конъюнкция без явного символа между литералами; между импликантами — крупный `+`.

**Копирование в буфер (по клику в поле ответа):**

- Отрицание: строка вида `¬X` (Unicode U+00AC + имя переменной).
- Дизъюнкция: `+` с пробелами по вкусу, но последовательно в одном стиле.
- Не использовать `getAnswer()`.

### 4.5. Соответствие строк и переменных (подтверждено заказчиком)

- Индекс строки `i` ∈ `[0, M)`.
- Набор переменных для строки `i`: бит `k` ( `0 ≤ k < N` ) равен `(i >> k) & 1`.
- **Переменная A — младший бит** (`k=0`), далее B, C, …
- Столбец значений функции: строка `i` = значение `func[i]` в смысле минимизатора (= `s[i]` на момент создания `Minimizer`).

**Бинарная строка в ячейке таблицы (текст ячейки всегда такой, п. 5.3 заказчика):**

- Для столбца с маской `mask` и строки `i`: обойти биты `k` от `0` до `N-1` в **возрастающем** порядке `k`; если `(mask >> k) & 1`, добавить символ `'0' + ((i >> k) & 1)`.
- Длина строки = `popcount(mask)`.
- Пример: столбец `ABD` при `N≥4` → три символа: биты A, B, D по возрастанию `k`.

**Заголовок столбца:** имена переменных для всех единичных бит `mask` в том же порядке возрастания `k` (например маска `10` в десятичной смысле зависит от N — в коде использовать биты).

## 5. Поведение UI (функциональные требования)

### 5.1. Ввод N

- `N` ∈ `[2, 7]` (QSpinBox или аналог).
- При изменении `N`: пересчитать `M = 1 << N`, **изменить длину вектора значений функции** (заказчик: *изменение N приравнивается к изменению значений функции* — обрабатывать **так же**, как правку `func`):
  - Рекомендуемая политика: при **увеличении** `N` — дополнить новые индексы значением `0`; при **уменьшении** — обрезать вектор до нового `M`.
  - После любого такого изменения: **сброс шагов минимизации** — новый `Minimizer` с текущим вектором и `N`, `stage` снова в начальном состоянии для нового объекта (0 до первого шага).

### 5.2. Столбец значений функции

- Одна колонка, `M` строк, строго та же **высота строки**, что у строк таблицы минимизатора (и той же вертикальной прокрутке).
- Одиночный клик: режим **ручного редактирования** ячейки.
- Двойной клик: **переключить** `0 ↔ 1` (без ожидания ввода с клавиатуры).
- Ручной ввод: пока не введён валидный символ `0` или `1`, значение **не фиксируется**; редактируемая ячейка подсвечена **полупрозрачным жёлтым**; после успешного ввода одного символа — перенести фокус редактирования на **следующую строку вниз** (или выйти из режима внизу таблицы — зафиксировать явно: остановиться на последней строке).
- Любое зафиксированное изменение вектора (в т.ч. после смены `N`): как минимум **пересоздать `Minimizer`** с новым `func` и тем же правилом сброса стадии.

### 5.3. Блокировка редактирования по стадии

- `returnStage()` ∈ `{1, 2, 3}` → **запрет** изменения столбца значений функции (и не инициировать пересоздание минимизатора от правок).
- `returnStage() == 0` → редактирование разрешено; изменение `func` → новый `Minimizer`, сброс визуализации шагов.
- `returnStage() == 4` → кнопка «Вперёд» **неактивна**; изменение столбца значений функции **эквивалентно** нажатию **«Вернуть»** (см. ниже).

### 5.4. Кнопки навигации

- **«Вперёд» / шаг:** вызов `makeStep()`, обновление таблицы и стадии; на стадии `4` — disabled.
- **«Вернуть»:** сброс **только шагов минимизации** (заказчик): заново создать `Minimizer` с **текущими** сохранёнными `func` и `N` (вектор значений не сбрасывать к нулям). UI возвращается к состоянию «до первого шага».
- **«Начать сначала»** (если в макете так названо или аналог): то же, что «Вернуть» по смыслу — **только** сброс минимизации, **без** сброса введённых значений функции.

### 5.5. Масштаб таблицы и столбца значений

- Кнопки увеличить/уменьшить масштаб таблицы и связанных левых колонок. **Горячие клавиши (Ctrl+, Ctrl− и т.п.) не требуются** (заказчик).
- Масштаб меняет **только** центральную табличную область и столбец значений (и панель наборов, если видна): общий множитель к высоте строки / ширине колонок таблицы.
- Верхняя и нижняя панели — **фиксированная высота** (по макету); не растягивать их масштабом таблицы.

### 5.6. Ответ и копирование

- После `stage == 4` и успешного `computeAnswer` отобразить минимальную ДНФ из `returnAns()`.
- **Клик** по полю ответа копирует текст в буфер обмена (формат с `¬` и `+`).
- Рядом с курсором при наведении на поле ответа: подсказка **`Копировать по клику`** (QToolTip или `setToolTip` на виджете).

### 5.7. Панель наборов

- Переключатель (стрелки в углу зоны таблицы): показать/скрыть дополнительный столбец слева от столбца значений (или между панелью наборов и таблицей — главное: визуально **дополнительный столбец к столбцу значений**, бинарные строки длины `N` для индекса строки в порядке `0 … M-1`).
- При открытой панели: обе колонки (наборы + значения) **закреплены** и не уезжают влево при горизонтальном скролле таблицы.

### 5.8. Закрепления и скролл

- Первая строка таблицы (заголовки масок столбцов) — **всегда видна** (не прокручивается вертикально вместе с телом); реализовать через frozen row, отдельный header widget или compositing.
- Столбец значений функции и панель наборов (если открыта) — **всегда видны**, не уезжают влево при горизонтальном скролле.
- Если таблица шире/выше окна: вертикальный скролл, горизонтальный скролл; **Shift + колесо мыши** — горизонтальный сдвиг (если платформа не делает сама — обработать вручную).
- Вертикальный скролл: **синхронизирован** между закреплёнными левыми колонками и основной таблицей (строгое выравнивание строк, п. «строгий визуальный маппинг»).

### 5.9. Визуал ответа («как в тетради»)

- Прямой литерал: крупная буква переменной.
- Отрицание: буква с **чертой над буквой** (Unicode combining overline U+0305 после символа, или другой приём с Arial; проверить отображение в Qt).
- Дизъюнкция: крупный `+`.
- В буфер обмена при копировании: `¬X`, не combining overline.

## 6. Расхождение формулировок ТЗ с кодом

В тексте задания столбцы иногда описаны как «по убыванию маски» при равном `popcount` — **в коде** используется **возрастание** маски (`lhs < rhs` в `PopcountComparator`). UI **обязан** следовать **фактическому порядку** `std::map` с этим компаратором.

## 7. Пошаговый план реализации (для отдельных чатов)

Каждый шаг — отдельная задача для ИИ; в конце шага проект должен компилироваться (кроме шага 0, где допустим пустой main). После каждого шага изменения **публикуются в GitHub** отдельным коммитом или логически сгруппированным набором коммитов.

### Шаг 0 — qmake и каркас приложения

- Корневой `dnf_minimizer.pro` (`TEMPLATE = app`, `QT += widgets`, `SOURCES`/`HEADERS` из `backend/` и **файлов в корне репозитория**, `INCLUDEPATH` для `backend` и при необходимости для корня).
- `main.cpp` **в корне**: `QApplication`, одно пустое `QMainWindow` или `QWidget`.
- Краткий README в корне **не добавлять**, если пользователь не просил.

### Шаг 1 — Модель сессии минимизации

- Класс в отдельных файлах **в корне** (например `minimizer_session.h` / `minimizer_session.cpp`): хранит `N`, `std::vector<ll> func`, `std::unique_ptr<Minimizer>` или объект на стеке с пересозданием.
- Методы: `setN`, `setFuncCell`, `toggleFuncCell`, `resetMinimization()`, `stepForward()`, `stage()`, `rebuildMinimizer()` при смене данных.
- Инкапсулировать правила: стадии 1–3 без правок func; стадия 4 — правка func вызывает `resetMinimization()`; смена `N` — resize func + `rebuildMinimizer()`.

### Шаг 2 — Верхняя панель по макету-изображению

- SpinBox `N`, кнопки шаг/назад/с начала, кнопки масштаба (без Ctrl), место под toggle панели наборов (если кнопка в углу таблицы — можно отложить на шаг 6).
- Подключить сигналы к контроллеру из шага 1.

### Шаг 3 — Нижняя панель: форматирование `MinDNF`

- Функции: `MinDNF` → строка для **экрана** (тетрадный стиль, Arial), `MinDNF` → строка для **clipboard** (`¬`, `+`).
- Виджет ответа: клик → `QGuiApplication::clipboard()->setText(...)`; `setToolTip("Копировать по клику")`.

### Шаг 4 — Столбец значений функции

- Кастомный `QWidget`/`QTableView` с одной колонкой: клик/даблклик/редактирование/жёлтая подсветка/фокус вниз по валидному вводу.
- Синхронизация высоты строк с таблицей (через общий `rowHeight` или сигнал от родителя).

### Шаг 5 — Панель наборов

- Второй столбец бинарных строк; show/hide; общая вертикальная прокрутка с таблицей.

### Шаг 6 — Таблица минимизатора

- Построение столбцов в порядке `returnTable()`.
- Заголовок: имена переменных по маске.
- Ячейки: текст по правилу раздела 4.5; фон: цвет по `table[mask][i]` с alpha.
- Закрепить header row и левые колонки; основная часть в `QScrollArea` или compositing.

### Шаг 7 — Скролл и Shift+wheel

- Довести синхронизацию скролла; полосы прокрутки; обработка wheel+Shift.

### Шаг 8 — Визуальное согласование с макетом-изображением

- Подогнать композицию, читаемые отступы и цвета **в духе** скриншота; без требования pixel perfect.

### Шаг 9 — Приёмочные сценарии (ручные)

- `N=2`, `N=7`; полный цикл 4 шагов; «Вернуть»; смена `func` на стадиях 0 и 4; блокировка на 1–3; копирование ответа; масштаб кнопками; панель наборов; выравнивание строк при скролле.

## 9. Дополнительные замечания для ИИ

- `Minimizer` наследует `QObject` — при добавлении сигналов в будущем не забыть `Q_OBJECT` и moc.
- Производительность при `N=7`, `M=128`, столбцов `127`: таблица умеренного размера; избегать полного пересоздания тяжёлых виджетов на каждый `paintEvent` без нужды.
- Не менять алгоритм в `minimizer.cpp` без отдельного задания.
- Если для frozen columns/rows окажется проще вынести заголовок в отдельный `QTableWidget` с одной строкой — допустимо, главное — отсутствие визуального сдвига и синхронность вертикали.
- При работе из браузера проверяйте актуальное содержимое файлов по **ссылкам blob** на GitHub для ветки **`implement-docs`**, а не только локальные черновики в чате.
